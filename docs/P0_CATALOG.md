# P0 Development Recipe Catalog

## Setup and Counts

Run `alembic upgrade head`, then `python -m app.scripts.seed_recipes` with the existing
local PostgreSQL configuration (`127.0.0.1:5433`). No API keys are needed. The command
reuses stable food source IDs and active recipe source/name identities; rerunning it
updates the same fixtures and recalculates recipe nutrition. It intentionally restores
the reviewed specifications for these development fixtures, not arbitrary imported foods.

| Meal Type | Recipes | Dairy-Free + Gluten-Free | Also <=20 Min With Requested Equipment |
| --- | ---: | ---: | ---: |
| breakfast | 10 | 7 | 7 |
| lunch | 10 | 8 | 8 |
| pre_workout | 10 | 6 | 5 |
| dinner | 10 | 8 | 7 |
| snack (separate) | 1 | 0 | 0 |

The equipment column assumes `[stovetop, oven, air_fryer]`. There are 41 recipes total,
37 newly added, using the existing 12 food fixtures. Forty recipes take <=20 minutes;
the retained Salmon Potato Spinach Plate takes 35. Pre-workout portions are small,
generally carbohydrate-focused rice, banana, oats, potato, or smoothie preparations;
they are not individually prescribed sports-nutrition advice.

All 41 recipes include real ordered steps. New recipes include prep/cook/assembly/serve
phases and timers where applicable; the existing Recipe Player snapshots these fields.
Cooked chicken and cooked rice are explicitly pre-cooked ingredients: their prior cooking
time is NOT included. Egg, potato, and salmon weights match their raw food fixtures.
Only `stovetop`, `oven`, `air_fryer`, `slow_cooker`, `microwave`, `blender` are accepted
equipment keys; no added recipe requires equipment outside this set.

## Structured Nutrition

No nutrition values were generated by AI or copied from an unverified API response.
The catalog reuses the existing approximate development food nutrient fixtures unchanged.
The deterministic recipe calculator rolls up gram quantities per 100g, then divides by
servings. All 15 definitions are present for every ingredient and recipe:

`calories`, `protein`, `carbohydrates`, `fat`, `fiber`, `calcium`, `iron`, `magnesium`,
`potassium`, `sodium`, `vitamin_a`, `vitamin_c`, `vitamin_d`, `vitamin_b12`, `folate`.

Recorded zeros are fixture values, not a fallback for missing nutrient data. Unit and
completeness checks remain unchanged. Complete data does not promise target coverage:
the solver returns actual totals, deviations, and micronutrient coverage independently.
This is not verified USDA or licensed production nutrition, and does not model nutrient
retention or cooked yield changes. A production catalog still needs verified food data.

## Explicit Ingredient-Content Reviews

`app/seed_data/allergen_reviews.py` is an explicit review register for each modeled food's
full ingredient specification. `seed_development_foods` uses the same canonical-code and
reference validator as `review_food_allergens`; no name-based inference occurs.

| Fixture | Reviewed Content | Allergen Codes |
| --- | --- | --- |
| Chicken breast | Plain cooked chicken only; no coating, marinade, or additives | `[]` |
| Cooked rice | Rice cooked in water only; no stock or butter | `[]` |
| Egg | Whole hen egg only | `[egg]` |
| Oats | Plain rolled oats; no additives, no gluten-free certification | `[]` |
| Milk | Plain cow milk | `[milk]` |
| Greek yogurt | Plain cultured cow milk; no gelatin, granola, or flavorings | `[milk]` |
| Spinach | Raw washed leaves; no dressing | `[]` |
| Broccoli | Raw washed florets; no coating or sauce | `[]` |
| Banana | Peeled raw flesh only | `[]` |
| Salmon | Raw unseasoned fish; no glaze, coating, or marinade | `[fish]` |
| Olive oil | Pure olive oil; no blended oils or flavorings | `[]` |
| Potato | Plain raw potato; no flour, butter, or seasoning mix | `[]` |

Each nonblank reference identifies the fixture specification, review date (2026-10-26),
the [FDA major-allergen reference](https://www.fda.gov/food/nutrition-food-labeling-and-critical-foods/food-allergies),
and that cross-contact was not assessed. These are reviewed modeled fixtures, NOT
retail-product or facility audits. `[]` means no listed allergen in that explicitly
defined ingredient content; it is never a universal allergen-free claim. Oats are not
tagged gluten-free because cross-contact/certification is unknown.

Existing fail-closed behavior is preserved: a supported saved profile allergy rejects
conflicting foods; any missing/invalid review or unsupported allergy excludes candidates.
The planner, automatic swap, and explicit `recipe_id` swap all use that same filtering.
Turning off `require_complete_nutrition` does not turn off allergen checks. No response
certifies medical safety, absence of every possible allergen, or cross-contact safety.

Dietary tags are authored explicitly per ingredient specification. Vegan recipes contain
no animal ingredients; vegetarian recipes exclude meat/fish; pescatarian recipes exclude
chicken; dairy-free recipes exclude milk/yogurt. No recipe receives `halal` without
sourcing evidence. As a result, this fixture catalog cannot satisfy a halal-only request;
it must fail closed until reviewed, appropriately sourced recipes are supplied.

Cooking instructions use the official
[safe minimum temperature guidance](https://www.foodsafety.gov/food-safety-charts/safe-minimum-internal-temperatures)
for reheated leftovers, fish, and egg dishes. Estimated cooking times are guides, not
substitutes for temperature/doneness checks.

## Frontend Contract and Verification

See [README P0 examples](../README.md#four-slot-daily-plans-p0) and
[API contract](API_SPEC.md#implemented-p0-daily-plan-contract) for exact requests.
All four required slots must be explicitly sent; legacy omitted-slot defaults remain.
`snack` remains an independent meal tag and standalone tracking resource.

On the inspected starting `main`, the two advertised GET endpoints and request-side
explicit recipe selection were absent. Minimal authenticated compatibility handlers were
added using the existing response schemas, owned records, and candidate/solver pipeline.
No unrelated frontend, tracking, optimization policy, or external integration was added.

`tests/test_p0_daily_plans.py` covers counts, all nutrient records, repeatable seeding,
diet/equipment eligibility, four-slot 201 persistence, the database check, pre-workout
CRUD/filtering/Recipe Player/swaps, reviewed/missing/conflicting allergen cases through
the solver, active plan logs, and owned/date-filtered standalone snack listing.

Verification on 2026-10-26: all 18 new P0 tests passed; the final complete suite against
an isolated PostgreSQL database returned `379 passed in 519.49s (0:08:39)`.
Upgrade from `20261021_0018` to the sole head `20261026_0019` was tested separately;
the existing development database retained all 8 plans and 24 items across the upgrade.
